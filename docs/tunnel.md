# 用内网穿透把服务端开放到外网

如果服务端运行在自己家里的电脑上（没有公网 IP），而队友或需要看板的人不在同一个局域网里，可以借助内网穿透工具，把本机的服务端端口映射成一个公网地址。

服务端只用**一个端口**（默认 `8000`）：网页、采集端上传（`/ws/ingest`）和看板推送（`/ws/monitor`）都走这个端口，所以只需要映射这一个端口。

## 开始之前

怎么选：队友在国内时，优先用 SakuraFrp 这类有国内节点的工具；队友在海外，或者大家都能稳定访问 Cloudflare 时，服务端内置的 Cloudflare 隧道最省事，改一个配置项就能用。服务端所在的电脑自己用 `http://127.0.0.1:端口/` 或局域网地址即可，不需要走外网地址。

1. **先在本机跑通。** 运行 `HeartRateServer.exe`，确认浏览器能打开 <http://127.0.0.1:8000/>。
2. **设置令牌。** 映射到公网后，任何知道地址的人都能访问，令牌是唯一的门槛。编辑 exe 旁边的 `heart-rate-server.json`，把 `"token"` 改成一串随机长字符串，然后重新打开服务端。之后采集端的“服务端令牌”和网页上的令牌都要填这一串。
3. **想清楚要不要加密。** 普通的 TCP 隧道是明文传输，令牌和心率都可能在传输途中被人看到。需要加密时，请选择能提供可信 HTTPS 证书的方式（见下文）。

穿透工具的客户端是从本机访问 `127.0.0.1:8000`，不需要在 Windows 防火墙里放行端口；只有局域网里的其他电脑直接访问时才需要。

## SakuraFrp（樱花 frp）

以下是和本项目相关的要点。注册、实名认证、下载启动器等步骤请按 [SakuraFrp 官方文档](https://doc.natfrp.com/) 操作，界面名称以 SakuraFrp 当前版本为准。

1. **创建隧道**：隧道类型选 **TCP**，本地 IP 填 `127.0.0.1`，本地端口填 `8000`（和 `heart-rate-server.json` 里的端口一致）。节点尽量选离大家近的。
2. **启动隧道**：在启动器里启动后，日志会给出连接地址，形如 `某某节点域名:12345`。
3. **所有人使用这个地址**：
   - 采集端的“服务端地址”填 `http://某某节点域名:12345`；
   - 网页看板和 OBS 浏览器源打开同一个地址。
4. **关于“自动 HTTPS”**：SakuraFrp 的 TCP 隧道可以开启“自动 HTTPS”，由它的客户端负责加密。但如果没有配置自己的域名和可信证书，用的就是自签名证书：浏览器会提示证书不安全，**采集端会直接拒绝连接**（它会校验证书）。所以要么不开，用上面的 `http://` 地址并设置好令牌；要么按 SakuraFrp 文档绑定自己的域名并配置可信 SSL 证书，之后所有人都用 `https://你的域名:端口`。

## Cloudflare Tunnel（免费，自带可信 HTTPS）

Cloudflare 的隧道客户端 `cloudflared` 可以免费使用，而且会自动提供浏览器和采集端都信任的 HTTPS 证书。

**国内网络可能打不开。** 我们实测时，同一个 `trycloudflare.com` 地址从境外访问一切正常；但在国内网络下，本机访问时通时断，失败时是 TLS 握手阶段就被重置（浏览器会显示连接被重置或无法建立安全连接）。把地址发给队友前，请先让对方在浏览器里打开试一下；打不开的话，改用下面的 SakuraFrp 等国内工具，或者双方都开代理。

**内置隧道（HeartRateServer.exe，推荐先试）：**

`HeartRateServer.exe` 已经内置了 cloudflared，不需要另外下载：

1. 用记事本打开 exe 旁边的 `heart-rate-server.json`，把 `"cloudflare_tunnel": false` 改成 `true`，保存。
2. 重新打开 `HeartRateServer.exe`。如果还没设置令牌，服务端会自动生成一个，并写回配置文件。
3. 几秒后窗口里会显示“外网地址（Cloudflare 隧道）已就绪”，以及地址和令牌。采集端“服务端地址”填这个 `https://…trycloudflare.com` 地址，“服务端令牌”填令牌；网页和 OBS 也打开这个地址。

如果窗口提示隧道创建失败，打开 exe 旁边的 `cloudflared.log` 查看原因，最常见的是当前网络连不上 Cloudflare。服务端窗口关闭（包括被强制结束）时，隧道会一起关闭，不会留下没人管理的外网入口。

**自己运行 cloudflared（从源码运行服务端时）：**

```powershell
cloudflared tunnel --url http://localhost:8000
```

两种方式得到的都是 Cloudflare 的免费 Quick Tunnel：

- 地址是 `https://随机名称.trycloudflare.com`，**每次启动都会变**；
- Cloudflare 官方说明它**只用于测试和开发，不保证稳定性**，并且最多同时处理 200 个请求；
- 不需要 Cloudflare 账号，也不需要域名。

**长期使用（需要自己的域名）：** 注册免费的 Cloudflare 账号，把域名交给 Cloudflare 托管，然后创建一个命名隧道并把某个子域名（例如 `hr.你的域名.com`）指向 `http://localhost:8000`。这样地址是固定的，所有人填 `https://hr.你的域名.com`。具体步骤见 [Cloudflare Tunnel 文档](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/)。

## 其他工具

| 工具 | 适合谁 | 说明 |
| --- | --- | --- |
| frp 自建 | 有自己的云服务器 | 在云服务器上运行 frps，本机运行 frpc，建一个 `type = "tcp"`、`localPort = 8000` 的代理；完全自己掌控，流量不经过第三方 |
| cpolar、花生壳等 | 想要图形界面、国内节点 | 用法和 SakuraFrp 类似：创建 TCP（或支持 WebSocket 的 HTTP）隧道，映射本地 `8000` 端口 |
| Tailscale、ZeroTier 等虚拟局域网 | 固定的一小群人 | 不暴露到公网：每个人安装客户端、加入同一个虚拟网络后，用服务端的虚拟 IP 访问（例如 `http://100.x.x.x:8000`）；最私密，但每个人都要安装 |

选择 HTTP 类型的隧道时，要确认它支持 WebSocket，否则网页能打开，看板却会一直显示“正在连接”。TCP 隧道没有这个问题。

## 流量估算

免费隧道通常有带宽和流量上限，值得算一下。服务端每收到一个人的一次心率（大约每秒一次），就会把**所有人**的最新状态推送给**每一个**打开的看板，每次推送的大小约为“人数 × 150 字节”。

例如 5 个人采集、10 个看板同时打开：每秒约 5 次推送 × 10 个看板 × 750 字节 ≈ 37 KB/s，约合每小时 130 MB。

直播时让观众看直播画面就好，只需要 OBS 那一台电脑打开看板，流量会小很多。

## 排查

- **本机能打开，外网打不开**：隧道没有启动，或者隧道的本地端口和服务端端口不一致。
- **网页能打开，看板一直“正在连接”**：隧道不支持 WebSocket（换成 TCP 隧道），或者地址填成了 `https://` 但隧道并没有提供 HTTPS。
- **采集端连接失败并提到证书（certificate）**：地址是 `https://`，但证书不是可信证书，见上面 SakuraFrp“自动 HTTPS”的说明。
- **`trycloudflare.com` 地址打不开，提示连接被重置**：多半是当前网络访问 Cloudflare 受限，见上面“国内网络可能打不开”。服务端窗口里显示“已就绪”只说明隧道和 Cloudflare 连上了，不代表队友那边的网络能访问。
- **看板显示“令牌无效”**：令牌和 `heart-rate-server.json` 里的不一致。
